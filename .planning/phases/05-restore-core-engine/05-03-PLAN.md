## What Was Done

1. **Compatible app reinstall with explicit user consent** — the app reinstalls compatible apps only through permitted installation paths:
   - App inventory from backup `app-inventory.json` is read: package name, version code, version name, install source
   - For each app, the UI presents a list of installable apps with "Install" checkbox
   - "Install" action uses Tauri's `opener` to launch the Android intent for installation via permitted paths only (Google Play Store URL, APK sideload through verified file picker, or `adb install` with user confirmation)
   - No silent installs: every app installation requires explicit user consent via confirmed button press
   - Install result recorded: success, failed (already installed, version mismatch, insufficient permissions)

2. **Manual marking of items requiring setup** — the app clearly marks app data, settings, permissions, and launcher elements that require manual setup or cannot be restored:
   - Per-app status labeling: " backed up" / "restorable" / "requires manual action" / "not supported"
   - Items requiring manual setup flagged with explanation badge:
     - App data: "Data not exported by app — re-enter credentials manually"
     - Permissions: "Permission reset required — grant in Settings → Apps → [App]"
     - Launcher elements: "Layout not exported — rearrange home screen manually"
     - Settings: "Settings not transferable — configure manually in app"
   - "Not supported" category for apps that opt out of BackupManager or use encrypted/remote backup
   - Each unsupported item shown in restore report with reason

3. **Restore report generation** — the app produces a restore report listing successes, partial restores, skips, and failures:
   - Report stored as `restore-report.json` at the root of the restore operation
   - Report structure:
     ```json
     {
       "restoreDate": "ISO-8601 timestamp",
       "sourceBackup": "name/id of backup",
       "destinationDevice": {"model", "androidVersion"},
       "summary": {
         "totalApps": 12,
         "successfulRestores": 8,
         "partialRestores": 2,
         "skipped": 1,
         "failures": 1
       },
       "successes": [
         {"packageName": "com.example.app", "status": "installed", "versionCode": 5}
       ],
       "partialRestores": [
         {"packageName": "com.example.partial", "status": "installed_data_missing", "note": "Some data required manual setup"}
       ],
       "skipped": [
         {"packageName": "com.example.skip", "reason": "Not supported — app opt out of BackupManager"}
       ],
       "failures": [
         {"packageName": "com.example.fail", "reason": "Installation failed — version code mismatch"}
       ],
       "manualActions": [
         {"type": "permission_grant", "description": "Grant storage permission for com.example.app in Android Settings"},
         {"type": "launcher_rearrange", "description": "Rearrange home screen layout for com.example.app"}
       ]
     }
     ```
   - Report offered for export as JSON/CSV/TXT via system share sheet
   - UI shows summary badges: "8 of 12 apps restored", "2 items require manual setup", "1 skipped", "1 failed"

4. **Safe resume of interrupted restore operations**:
   - Restore state saved at each chunk boundary (similar to backup pause/resume)
   - On disconnect during restore: save current chunk offset, partially installed apps, and computed checksums
   - On reconnect: resume from last saved chunk offset; skip already-installed apps (check via `adb shell pm list packages`)
   - Timeout handling: if device does not reconnect within 60 seconds, offer "Cancel restore" or "Wait and retry"
   - Partial state never corrupted: if a chunk fails, mark it CORRUPT and continue to next chunk; already-processed chunks are not re-processed
   - Restore resume emits `"restore-resume-progress"` with `{offset, chunksTotal, chunksCompleted, reason: "DISCONNECT"` or `"TIMEOUT"`
