## What Was Done

1. **Destination device detection** — the app identifies connected Android devices via ADB and extracts model, manufacturer, and Android version metadata:
   - `list_devices()` in `src-tauri/src/adb.rs` polls `adb devices -l` and populates `DeviceInfo` with serial, status, model, manufacturer, android_version, sdk_version
   - UI (`DeviceStatusCard.tsx`) displays device specs: model, manufacturer, Android version, SDK version, battery level, storage free/total
   - `"device-poll"` reactive event emitted every 1.5s from Rust backend to keep UI updated

2. **Compatibility checking against backup source validation** — before restore, the app verifies the backup is from a supported source per the Phase 1 go/no-go decision:
   - Backup manifest `sourceModel`, `sourceAndroidVersion` fields are read and compared to the destination device's model and Android version
   - Compatibility rule: destination Android version must be equal to or newer than the source device's Android version that created the backup
   - If backup source is unverified or unsupported (per Phase 1 NO-go), restore is blocked with error: "Backup source not recognized — this backup was created for a virtual-source pathway that is not supported. Use post-setup MTP/ADB restore instead."
   - Compatibility result stored in manifest: `sourceCompatibility` = "COMPATIBLE" / "INCOMPATIBLE" / "UNVERIFIED"

3. **User-facing compatibility summary** — the restore preflight screen shows:
   - Source device model and Android version
   - Destination device model and Android version
   - Compatibility status: COMPATIBLE / INCOMPATIBLE / UNVERIFIED
   - Action: "Proceed with restore" / "Select different backup" / "Start new backup"
